A collection's items can come from another system, such as the site's database, while its fields, page design, and address stay in the admin panel. The config's new `collections` names each collection's source, a module whose default export reads its items (`defineCollectionSource()` in `@goodfellow-cms/core`), with options it's given: `collections: { jobs: { source: "./lib/jobs.ts", options: { table: "jobs" } } }`. Items are checked as items' files are, with only the values of the collection's own fields, and one that doesn't fit is left out with a warning, so a bad row never stops the site; item files left in a sourced collection's folder aren't read (`loadSiteContent(files, { sourced })`). `goodfellow build`, `goodfellow dev`, and `goodfellow-next finish` load the modules themselves; Next.js sites pass them to `goodfellowPages()` and `goodfellowApi()` as `sources`, since Next.js bundles only what's imported. Pages, feeds, calendars, the content API, and the site checks show the source's items as the collection's (`withSourcedCollections()`), and `sourceChanges()` says which pages to render again when a source's `changed()` reports changes, for a site's own route to pass to `revalidatePath()`. Each source is read on its own: one that can't be read just now shows the items it gave last in the same process, with a warning, and one never read stops the build or the page, rather than show the collection empty. `loadSourceModules()` in `@goodfellow-cms/core/node` loads the config's sources' modules for tools that load them themselves. The admin panel shows them read-only, from a full-stack site's server (`/api/goodfellow/collections/<id>/items`), counts their pages in its publish checks, moves their pages with a new address pattern, and names the source in the collection's settings; where a source can't be read just now, the collection says so with **Try again**, and a change to its settings waits until it can be, while anything else is published without checking links that could go to its items' pages. Claude's tools list no items for a sourced collection, say where they come from, and won't change them. Next.js sites make their sources only once the site or its items are read, so a source that can't be made fails only those. The site's description names each source's module, never its options.
