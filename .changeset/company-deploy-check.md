Full-stack sites' **Deploy** workflow checks what the build job built before the deploy job, which holds the Cloudflare token and the site's keys, gives it to wrangler. The build runs the site's code and every package it loads, and wrangler follows the config it writes, which could name a command to run before uploading, or files outside `dist/` to upload with the Worker, such as the deploy's own environment. The new `scripts/check-build.ts` takes the build's config only where it's `wrangler.jsonc`'s, leaving none of its settings out, with the build's own files in `dist/` and no links. It doesn't read the Worker's code, which runs with the site's keys, so a hostile package could still put code there. Sites made with `create-goodfellow --server cloudflare` or the full-stack setup page before this release keep their copy: copy the example's `scripts/check-build.ts` into the site's code repository, and add its **Check what the build handed over** step to the deploy job in `.github/workflows/deploy.yml`, after the build's files are downloaded and before `npm ci`, keeping the site's own content repository and other settings in the file.
